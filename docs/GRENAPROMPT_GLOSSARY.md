# Grenaprompt Glossary

## Lexique canonique du Grenaprompt et du FGP

**Version :** 0.1 - Base terminologique  
**Auteur :** Xavier Fleriag / Twins Productions  
**Statut :** Glossaire de consolidation  
**Perimetre :** Grenaprompt, FGP et termes fondateurs uniquement

---

## 1. Objet du glossaire

Ce glossaire fixe les termes essentiels du Grenaprompt et du FGP afin d'eviter les confusions entre langage, structure, emotion, technique et gouvernance.

Il sert de reference courte pour lire les documents fondateurs :

- `GRENAPROMPT_FOUNDATIONAL_WHITEPAPER.md`
- `FGP_FRAMEWORK_GRENAPROMPT.md`

Regle generale :

```text
Le Grenaprompt definit le langage hybride.
Le FGP definit le cadre de gouvernance autour de ce langage.
```

---

## 2. Termes fondamentaux

### Grenaprompt

Langage hybride humain-machine construit a partir de JSON, d'anglais et de francais.

Formule canonique :

```text
Grenaprompt = JSON + EN + FR
```

Role : structurer une instruction pour qu'elle soit lisible par la machine tout en conservant le sens humain.

---

### GrenaPrompt

Graphie historique du terme Grenaprompt.

Cette forme peut apparaitre dans des archives, anciens documents ou formulations initiales.

Regle recommandee :

```text
Utiliser "Grenaprompt" comme graphie publique principale.
Conserver "GrenaPrompt" pour references historiques si necessaire.
```

---

### FGP

Acronyme de **Framework GrenaPrompt**.

Le FGP est le cadre de gouvernance, stabilisation et audit autour du Grenaprompt.

Formule canonique :

```text
FGP = Gouvernance + Stabilisation + Audit du Grenaprompt
```

Le FGP n'est pas le langage. Il encadre le langage.

---

### JSON

Contenant structurel du Grenaprompt.

Role : organiser l'information sous forme de cles, valeurs, objets, listes, contraintes et hierarchies.

Dans le Grenaprompt, JSON sert a donner une forme stable a l'intention.

Formule courte :

```text
JSON = structure
```

---

### EN

Couche anglaise du Grenaprompt.

Role : exprimer la precision technique, les actions operationnelles, les contraintes d'execution et les formulations proches des conventions numeriques ou developpeur.

Formule courte :

```text
EN = precision technique
```

Exemples :

```text
validate the constraints
define output format
apply strict reasoning
preserve source integrity
```

---

### FR

Couche francaise du Grenaprompt.

Role : porter l'emotion, l'intention, le contexte humain, la nuance et la sensibilite.

Formule courte :

```text
FR = emotion + intention + contexte humain
```

Exemples :

```text
respecter l'intention d'origine
ne pas trahir la nuance
repondre avec justesse
garder une presence humaine
```

---

### Double lecture

Principe selon lequel une instruction Grenaprompt doit etre lisible par deux destinataires en meme temps :

```text
machine = structure exploitable
humain = intention comprehensible
```

La double lecture est le coeur du Grenaprompt.

---

### Instruction hybride

Instruction qui combine structure machine, precision technique et intention humaine.

Une instruction hybride peut contenir JSON, EN et FR dans un meme bloc ou un meme champ.

Exemple :

```json
{
  "task": "EN: audit the structure | FR: verifier sans casser l'intention humaine"
}
```

---

### Couche technique

Partie de l'instruction qui indique ce qui doit etre fait, comment le faire, dans quel format, avec quelles contraintes et quel niveau de precision.

Dans le Grenaprompt, elle est principalement portee par EN.

---

### Couche emotionnelle

Partie de l'instruction qui porte la nuance, la sensibilite, le ton, l'intention et la resonance humaine.

Dans le Grenaprompt, elle est principalement portee par FR.

---

### Contenant structurel

Cadre qui organise l'instruction pour eviter la dispersion.

Dans le Grenaprompt, le contenant structurel est principalement JSON.

---

## 3. Termes FGP

### Gouvernance

Ensemble des regles et mecanismes qui encadrent l'usage d'une instruction hybride.

Dans le FGP, la gouvernance vise :

```text
coherence
securite
tracabilite
audit
adaptabilite controlee
```

---

### Stabilisation

Processus qui empeche une instruction ou un comportement de deriver trop rapidement.

La stabilisation ne signifie pas immobilite. Elle signifie controle de la variation.

---

### Audit

Verification structuree d'un etat, d'une reponse, d'un comportement ou d'un changement.

Dans le FGP, l'audit sert a detecter les derives, contradictions, oublis de contraintes et pertes d'alignement.

---

### LOCK

Mecanisme de verrouillage de stabilite.

Role : figer temporairement certains parametres centraux pour reduire les derives.

Regle canonique :

```text
Le LOCK stabilise. Il ne rend pas une erreur intouchable.
```

---

### Checkpoint

Point de controle periodique destine a verifier la coherence, la stabilite et l'alignement.

Regle canonique :

```text
Le checkpoint audite avant de corriger.
```

---

### Autoprompt

Instruction de controle interne utilisee pour verifier une derive, une contradiction ou une perte d'alignement.

Regle canonique :

```text
L'autoprompt controle. Il ne remplace pas l'action utile.
```

---

### Journalisation

Conservation structuree des evenements utiles : changements, decisions, points de controle, etats importants.

La journalisation doit rester proportionnee.

Regle canonique :

```text
Tracer ce qui gouverne. Ne pas stocker ce qui expose inutilement.
```

---

### Empreinte

Identifiant, signature ou hash permettant de verifier l'integrite d'un element.

Une empreinte peut servir a comparer deux etats ou a prouver qu'un contenu n'a pas ete modifie.

---

### Hash

Type d'empreinte calculee a partir d'un contenu.

Dans le contexte FGP, le hash sert surtout a l'integrite et a l'auditabilite.

---

### Confidentialite

Principe selon lequel les donnees sensibles ne doivent pas etre stockees, exposees ou reutilisees sans protection ni raison claire.

Regle canonique :

```text
Une trace utile ne doit pas devenir une fuite de donnees.
```

---

### Transparence

Capacite a expliquer les regles importantes, limites, incertitudes et decisions structurantes sans exposer inutilement les details internes.

Regle canonique :

```text
La transparence sert la confiance, pas la surcharge.
```

---

### Adaptabilite controlee

Capacite d'ajuster le comportement selon un contexte, un client ou un projet sans perdre les principes fondamentaux du cadre.

Regle canonique :

```text
Adapter le comportement, jamais dissoudre le cadre.
```

---

## 4. Distinctions importantes

### Grenaprompt vs FGP

```text
Grenaprompt = langage hybride
FGP = gouvernance du langage hybride
```

Le Grenaprompt formule. Le FGP encadre.

---

### JSON pur vs Grenaprompt

```text
JSON pur = configuration
Grenaprompt = configuration + technique + intention humaine
```

---

### Prompt bilingue vs Grenaprompt

Un prompt bilingue traduit ou alterne deux langues.

Un Grenaprompt articule JSON, EN et FR selon une double lecture machine-humain.

---

### Emotion vs decoration

Dans le Grenaprompt, l'emotion n'est pas un embellissement.

Elle porte l'intention, le contexte, la nuance et la resonance humaine.

---

### Structure vs rigidite

Dans le Grenaprompt, la structure n'est pas une prison.

Elle permet de rendre l'intention exploitable sans la rendre froide ou vide.

## 7. Conclusion

Ce glossaire fixe la base terminologique.

Le Grenaprompt doit rester compris comme un langage hybride :

```text
JSON pour structurer.
EN pour preciser.
FR pour humaniser.
```

Le FGP doit rester compris comme le cadre de gouvernance autour de ce langage :

```text
LOCK pour stabiliser.
Checkpoints pour verifier.
Autoprompts pour controler.
Journalisation pour tracer.
Confidentialite pour proteger.
Transparence pour expliquer.
Adaptabilite controlee pour evoluer.
```

Formule finale :

```text
Grenaprompt donne la forme a l'instruction.
FGP donne la discipline a son usage.
```
